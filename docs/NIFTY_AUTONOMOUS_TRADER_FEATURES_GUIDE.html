1. Executive Summary & Capabilities Matrix

The NIFTY Autonomous Trader is a dedicated autonomous agentic trading system built to behave like a disciplined human trader. It is not an algorithmic black-box or a hard-coded indicator bot. Instead, it pairs a cognitive reasoning intelligence (AI Brain) with an autonomous operating agent (Hermes), gated by non-negotiable deterministic risk circuit breakers and operating over real browser interfaces.

Core Safety Mandate
Live real-money broker execution is permanently disabled in code. All execution flows terminate inside the Sensibull Virtual Portfolio paper-trading sandbox.

2. Detailed Feature Breakdown by Subsystem

Feature Domain 1: Cognitive Reasoning Layer (AI Brain)
Cognitive
Replaces brittle heuristic strategy rules with high-order contextual market reasoning.
  • ModelRouter Dynamic Routing: Task-tiered routing engine abstracting model providers (Google Gemini 2.5 Flash/Pro, OpenRouter, DeepSeek, Claude) with automatic failover and retry logic.
  • 17-State Market Reasoning Machine: Enforces disciplined transitions (NO_TRADE → WAIT → WATCH → DEVELOPING → CANDIDATE). The Brain never forces a trade when evidence is ambiguous.
  • Regime & Structural Synthesis: Identifies macro regimes (TRENDING_UP, TRENDING_DOWN, RANGING, EXPANDING, CONTRACTING, UNCLEAR) and structural patterns (Higher Highs/Lows, Breakout Attempts, Rejections).
  • Strict Pydantic Anti-Hallucination Contracts: Validates model outputs against strict schemas (BrainOutput, Direction, SetupStatus).
  • Brain Reasoning Audit Store: Logs every prompt, token count, reasoning summary, uncertainty, and model output into data/brain_history.db.
Feature Domain 2: Multimodal Sensory & Perception Layer
Perception
Provides the eyes of the autonomous agent across browser and numerical market feeds.
  • Chrome CDP Integration: Connects to Google Chrome via remote debugging port 9222 with persistent profile storage in data/browser_profile/.
  • One-Time Secure Login (browser-login): Enables users to sign into Sensibull, TradingView, and Google interactively without exposing passwords to LLMs or scripts.
  • TradingView Multimodal Observer: Captures high-resolution canvas screenshots of NIFTY charts for visual vision reasoning alongside DOM price levels.
  • Sensibull Option Chain Matrix: Scrapes real-time Put-Call Ratios (PCR), Max Pain strikes, Call/Put Open Interest buildups, and strike implied volatilities.
  • Local Lightweight Chart Server: Serves a deterministic, local TradingView Lightweight Charts canvas via internal HTTP, eliminating third-party rate limits and captchas.
  • Cross-Source Price Verifier: Cross-checks numerical feed prices against browser DOM text, halting on divergence > ₹5.00.
Feature Domain 3: Hermes Operator & Collaborative Orchestration
Orchestration
Coordinates market cadence and drives interactive multi-turn dialogue with the AI Brain.
  • Autonomous Candle Boundary Scheduler: Schedules observation runs strictly at 15-minute and 1-hour candle completion boundaries, sleeping between intervals without CPU spin-locking.
  • Multi-Turn Collaborative Inquiry Loop: Hermes presents market data; Brain requests missing context (e.g. "Check 25300 PE Open Interest buildup"); Hermes executes browser tools to retrieve evidence; Brain finalizes trade candidate.
  • Candidate Halting: Immediately halts upon reaching CANDIDATE, passing the proposal downstream to the Safety Guard without unauthorized broker placement.
  • Operator Instruction Subsystem: Allows human steering via CLI (instruction, instruction-list) with deterministic regex boundaries rejecting prohibited directives.
Feature Domain 4: Deterministic Safety Guard (Locked Risk Engine)
Safety Guard
Non-bypassable circuit breakers standing between cognitive reasoning and broker execution.
  • Portfolio Daily Loss Cap (₹2,000): Hard circuit breaker halting all system trading if cumulative daily loss reaches ₹2,000.
  • Instrument Daily Loss Cap (₹1,000): Independent ₹1,000 daily loss stop for NIFTY and BANKNIFTY.
  • Daily Trade Frequency Limit: Maximum 3 trades per day for NIFTY, and maximum 3 trades per day for BANKNIFTY.
  • Strict 1-Lot Position Sizing: Mandates exactly 1 lot per trade (65 qty for NIFTY, 30 qty for BANKNIFTY); rejects excess lots instantly.
  • Single Active Instrument Policy: Only 1 instrument allowed to be active concurrently. Multi-symbol overlapping is strictly blocked.
  • Mandatory 1:3 Risk-to-Reward (R:R): Rejects any trade plan where the reward-to-risk ratio falls below 1:3.0.
  • Intraday Timing Filters: Blocks new entries during opening volatility (09:15–09:25 IST) and pre-close square-off windows (after 15:15 IST).
  • Paper Mode Verification: Checks Sensibull DOM badges to guarantee paper trading environment; aborts if live account detected.
  • Fail-Closed Design: Any unknown position or platform error defaults immediately to a safe, non-executing state.
Feature Domain 5: Sensibull Paper Broker & Execution Lifecycle
Execution
Executes virtual option orders directly in Sensibull Virtual Portfolio.
  • DOM Action Dispatcher: Interacts with Sensibull UI elements to submit Buy/Sell virtual orders for NIFTY calls and puts.
  • Execution Idempotency: Uses deterministic candidate hashing to prevent accidental duplicate orders.
  • Remote-to-Local State Reconciler: Polls and verifies that placed virtual orders reflect accurately in Sensibull's position table.
  • Complete 10-Stage Lifecycle: Manages state progression from NO_POSITION → TRADE_INTENT → SAFETY_AUTHORIZED → POSITION_OPEN → POSITION_CLOSED.
Feature Domain 6: Autonomous Trade Monitoring & Position Management
Monitoring
Continuously monitors open positions like a disciplined human trader.
  • Continuous Unrealized P&L Tracking: Reads real-time position prices and calculates active profit/loss.
  • Meaningful Move Gating: Triggers cognitive Brain reassessments only on material price moves (> 1.0%) or structural candle closures, avoiding noise.
  • Cognitive Reassessment Actions: Dispatches Brain directives: CONTINUE, TRAIL_STOP, or CLOSE_NOW.
  • Automated Square-Off: Automatically executes complete liquidation on stop-loss hit or market close (15:20 IST).
  • Lifecycle Audit Store: Logs all monitoring cycles, P&L traces, and reassessments into data/position_monitoring.db.
Feature Domain 7: Performance Analysis & Experience Memory
Experience
Extracts grounded empirical lessons from completed trades without mutating code.
  • Decoupled Post-Mortem Analyzer: Separates Decision Quality, Execution Quality, and Market Outcome. Never equates Profit = Good Reasoning or Loss = Bad Reasoning.
  • Multi-Source Timeline Reconstruction: Reconstructs entry, monitoring, and exit timelines using verified timestamps.
  • Behavioral Taxonomy Tagging: Labels trades under structural tags (BREAKOUT, RANGE_BOUNCE, VOLATILITY_EXPANSION).
  • Descriptive Performance Statistics: Calculates Win Rate, Profit Factor, Expectancy, and Average Duration stored in data/experience.db.
  • Anti-Rule Safety Guard: Rejects imperative rules ("NEVER BUY") to ensure memories remain descriptive historical records.
Feature Domain 8: Segregated Hermes Data Research Zone
Research Lab
An isolated quantitative research laboratory operating independently of live trading.
  • Dhan Broker Data Adapter: Abstract DhanDataAdapter with offline deterministic MockDhanDataAdapter generating synthetic OHLCV+OI bars, option chains, and market depth. Zero API keys required at this stage; ready for future live Dhan plug-in.
  • Data Engineering Pipeline: Validates OHLC mathematical invariants, rejects corruptions, deduplicates bars, and resamples 1M bars into 5M, 15M, 1H, and 1D timeframes.
  • Quantitative Indicator Preparation: Computes EMA (9, 20, 50, 200), RSI (14), MACD (12, 26, 9), ATR (14), Intraday VWAP with ±1.5 StdDev bands, Volume SMA ratios, and OI change percentages.
  • Empirical Research Engine: Formulates falsifiable hypotheses, backtests historical forward returns, and calculates sample sizes, win rates, profit factors, and binomial p-values.
  • Aggressive Contradiction Search: Actively hunts for counter-examples and failure regimes where setups fail, calculating false positive rates and spawning follow-up research questions.
  • Independent Dynamic Scoring Engine: Strictly enforces the dynamic importance invariant (NO fixed or static percentage weights): 
    Total Score = Σ (Segment Score_i × Segment Importance_i) / Σ Segment Importance_i
    Dynamically weights segments based on active regime (trending vs consolidating vs volatile).
  • Negative Knowledge Catalog: Preserves failed hypotheses in research_memory.db so Hermes remembers which ideas have been statistically disproven.

4. Physical Data Storage & Database Layout

All data persistence is strictly segregated across dedicated SQLite databases and sandbox directories:

data/
|-- browser_profile/             # Dedicated Chrome user profile (session cookies, logins)
|-- candle_cache.db              # 1H and 15M historical candlestick cache
|-- brain_history.db             # Full trace of Brain reasoning prompts, outputs & states
|-- agent_instructions.db        # Operator manual instructions and directives
|-- paper_positions.db           # Sensibull paper trades, order history & position states
|-- position_monitoring.db       # Real-time monitoring cycles, P&L traces & reassessments
|-- experience.db                # Post-trade post-mortems, metrics & taxonomy records
`-- hermes_research/             # STRICTLY SEGREGATED RESEARCH DATABASES
    |-- market_data.db           # Normalized bars, raw payloads, engineered feature sets
    |-- research.db              # Questions, pattern definitions, hypotheses, backtest results
    |-- assessments.db           # Dynamic assessments, dynamic segment weights & scores
    `-- research_memory.db       # Verified findings, failed hypotheses (negative knowledge)
