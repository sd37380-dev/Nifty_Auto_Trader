1. Architectural Philosophy & Core Invariants

The NIFTY Autonomous Trader is engineered as an autonomous agentic trading system governed by strict mathematical, operational, and physical segregation guarantees. Traditional trading bots often fail because they tightly couple heuristic indicators, execution code, and risk rules into brittle monolithic scripts.

This architecture is governed by five non-negotiable principles:

  1. Cognitive Separation: The AI Brain (Google Gemini / ModelRouter) acts solely as an analytical intelligence layer. It never directly executes trades or modifies safety parameters.
  2. Hermes as Autonomous Operator: Hermes acts as the disciplined human trader—gathering information, cross-checking charts, scheduling observation intervals, and submitting trade proposals.
  3. Deterministic Safety Guard (Locked): Hard-coded circuit breakers (Max loss per trade, daily cumulative loss stop, maximum lot limits, and time-of-day filters) stand between the AI and broker execution. No prompt or cognitive reasoning can override these safeguards.
  4. Independent Dynamic Scoring (No Fixed Weights): In quantitative assessment, rigid indicator weights (e.g. Trend=25%, Momentum=20%, Volume=20%) are strictly prohibited. The system dynamically assigns importance weights based on real-time market regimes.
  5. Physical & Logical Zone Segregation: The Research & Intelligence Zone operates in a completely isolated silo with its own SQLite database storage. It has zero coupling with order routing or position management.
Operational Safety Invariant
Live broker trading is permanently disabled at the code and configuration level. All automated execution flows terminate inside the Sensibull Virtual Portfolio paper-trading environment.

3. Detailed Subsystem Specifications

3.1 Sensory & Perception Layer

The sensory layer is the eyes of the autonomous trader. It interfaces directly with Chrome CDP and numerical APIs to produce unified, verified market context:

  • Chrome CDP Session: Runs an isolated instance of Google Chrome attached via remote debugging port 9222. State, logins, and cookies persist across cycles in data/browser_profile/.
  • TradingView Multimodal Observer: Captures high-resolution canvas screenshots of NIFTY charts alongside DOM data to enable multimodal visual reasoning by the cognitive brain.
  • Sensibull Observer: Gathers real-time option chain matrices, Put-Call Ratio (PCR), Open Interest concentrations, and strike-level implied volatilities.
  • Local Lightweight Chart Server: Serves a deterministic, local TradingView Lightweight Charts canvas via an internal HTTP server, eliminating external captchas, rate limits, or CDN outages.
  • Cross-Verification Engine: Automatically checks numerical candle close prices against browser DOM text. If price divergence exceeds ₹5.00, reasoning halts with an observation conflict warning.

3.2 Hermes Orchestration & Collaborative Layer

Hermes does not decide whether a trade setup is mathematically sound—that is the Brain's domain. Instead, Hermes acts as the professional human operator:

  • Autonomous Event Loop: Coordinates market cadence, scheduling observation runs strictly on 15-minute and 1-hour candle completion boundaries. Between boundaries, Hermes sleeps without consuming CPU cycles.
  • Multi-Turn Collaborative Inquiry: Executes an interactive dialogue with the Brain:
    1. Hermes provides current market data.
    2. Brain identifies missing context (e.g. "Inspect 25300 PE Open Interest buildup").
    3. Hermes uses browser tools to retrieve that exact evidence.
    4. Brain synthesizes the complete picture to reach a final trade candidate or wait decision.
  • Operator Instruction Registry: Enables human supervision through CLI commands (instruction, instruction-list), allowing operators to inject higher-priority execution constraints.

3.3 Cognitive Reasoning Layer (AI Brain)

The Brain layer transforms multi-source perceptions into disciplined market reasoning using large language models:

  • ModelRouter: Abstracts API calls across providers (Gemini 2.5 Flash, Gemini Pro, OpenRouter) with automatic fallback and retry logic.
  • Strict Pydantic Contracts: Output is parsed into validated schemas (BrainOutput, Direction, SetupStatus) ensuring zero hallucinated actions.
  • 17-State Machine: Enforces disciplined progression from NO_TRADE → WAIT → WATCH → DEVELOPING → CANDIDATE.
  • Brain History Store: Logs all reasoning chains, uncertainties, and model outputs into data/brain_history.db for complete traceability.

3.4 Deterministic Safety Guard

The Safety Guard is a non-bypassable code module locked between the cognitive layer and broker execution:

Circuit Breaker Configuration Action on Violation
Portfolio Daily Loss Cap ₹2,000 hard stop (realized + unrealized across all instruments) Halts entire trading system for remainder of day
Instrument Daily Loss Cap ₹1,000 max daily loss per instrument (NIFTY & BANKNIFTY) Halts trading operations on that specific instrument for the day
Daily Trade Frequency Limit Max 3 trades/day for NIFTY, Max 3 trades/day for BANKNIFTY Blocks subsequent trade order entries for that instrument
Strict Position Sizing Exactly 1 lot per trade (65 qty NIFTY / 30 qty BANKNIFTY) Instantly rejects any order requesting > 1 lot
Single Active Instrument Policy Only 1 instrument traded at a time (concurrent instruments = 1) Rejects order in second symbol while another position is open
Risk-to-Reward Ratio (R:R) Mandatory minimum 1:3 (3.0) reward-to-risk ratio Rejects proposed trade plan if R:R is below 1:3
Intraday Timing Window No new entries 09:15–09:25 or after 15:15 IST Blocks entry; forces WAIT state
Paper Mode Guard Strict DOM confirmation of virtual badge Emergency abort if live broker detected

3.5 Paper Broker & Autonomous Trade Monitoring

Executes and manages approved orders inside Sensibull:

  • Sensibull Paper Broker: Places virtual market and limit orders by dispatching targeted DOM events. Reconciles local trade memory with remote Sensibull ground truth.
  • Idempotency Enforcement: Prevents duplicate orders by assigning deterministic hash keys to trade candidates.
  • Autonomous Position Monitor: Continuously monitors open positions. When market price shifts materially, the monitor calls the Brain for reassessment (CONTINUE, TRAIL_STOP, CLOSE_NOW).
  • Emergency Square-Off: Automatically executes complete position liquidation on stop-loss breach or market close (15:20 IST).

3.6 Performance Analysis & Experience Memory

Analyzes closed trades to extract long-term experiential knowledge without modifying code:

  • Post-Trade Analyzer: Reconstructs the trade lifecycle from entry to exit. Separates Market Outcome, Reasoning Quality, and Execution Fidelity.
  • Behavioral Taxonomy: Labels trades under structural regimes (e.g., TREND_CONTINUATION, FAILED_BREAKOUT, VOLATILITY_EXPANSION).
  • Cumulative Performance Metrics: Calculates historical Win Rate, Profit Factor, Expectancy, and Average Holding Duration stored in data/experience.db.

3.7 Segregated Research & Intelligence Zone

A dedicated quantitative research zone completely isolated from trading execution. It allows Hermes to formulate empirical hypotheses, backtest patterns, conduct aggressive contradiction searches, and generate dynamically weighted assessments:

Dynamic Scoring Formula:
Total Score = Σ (Segment Scorei × Segment Importancei) / Σ Segment Importancei
  • Dhan Broker Data Adapter: Features an abstract interface (DhanDataAdapter) and an offline synthetic provider (MockDhanDataAdapter) generating realistic OHLCV+OI bars, option chains, and market depth. Ready to receive live Dhan API feeds with zero architectural changes.
  • Data Engineering Zone: Validates mathematical OHLC invariants, cleans corruptions, resamples 1M bars into 5M/15M/1H/1D bars, and computes technical feature sets (EMAs, RSI, MACD, ATR, VWAP bands, OI change %).
  • Hermes Empirical Research Engine: Systematically tests trading hypotheses across historical data. Calculates sample sizes, win rates, profit factors, and statistical p-values.
  • Contradiction Search: Actively hunts for counter-examples and failure regimes where candidate setups fail, deriving false positive rates.
  • Independent Dynamic Scoring Engine: Replaces rigid indicator weights with dynamic importance values derived from the prevailing regime.
  • Negative Knowledge Catalog: Preserves failed hypotheses in research_memory.db so Hermes remembers which ideas have been statistically disproven.
